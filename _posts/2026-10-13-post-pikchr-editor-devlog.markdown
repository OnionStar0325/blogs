# [개발일지] Pikchr Editor 개발기: Antigravity CLI 바이브 코딩을 통한 비주얼 에디터 구현 과정

기술 문서나 아키텍처 다이어그램을 다룰 때 텍스트 기반 다이어그램 도구는 버전 관리와 문서 임베딩 측면에서 유용합니다. 그중 [Pikchr](https://pikchr.org)는 C 기반으로 작성되어 간결한 문법으로 SVG 결과물을 생성하는 마크업 언어입니다.

다만 Pikchr 스크립트를 작성하다 보면 다음과 같은 불편이 있습니다:

1. **문장 식별의 어려움**: 렌더링된 캔버스의 특정 요소가 코드의 어느 문장에 해당하는지 한눈에 파악하기 어렵습니다.
2. **문법 체득의 어려움**: 도형 뒤에 사용 가능한 속성 키워드나 앵커 표기법, 상대 위치 표현 등을 매번 레퍼런스에서 확인해야 합니다.

다이어그램이 복잡해질수록 렌더링된 SVG와 텍스트 코드 사이를 대조하는 데 시간이 많이 소요됩니다.

이러한 문제를 줄이기 위해 Pikchr 문법 작성을 보조하고 문장 식별을 돕는 웹 기반 도구인 [Pikchr Editor](https://github.com/OnionStar0325/pikchr-editor)를 제작했습니다.

이 프로젝트는 소스 코드를 직접 한 줄씩 작성하지 않고, Antigravity CLI를 활용하여 대화형 프롬프트와 피드백을 통해 기능을 구현하는 바이브 코딩(Vibe Coding) 방식으로 진행되었습니다. 기획 및 요구사항 정의, 실사용 테스트를 통한 문제점 식별, 그리고 AI 에이전트를 통한 수정 및 검증 과정을 정리했습니다.

## 1. 초기 기획 및 아키텍처 설계

초기 단계에서는 바로 코드 구현에 들어가지 않고, 화면 구조와 동작 요구사항을 정의한 후 설계 문서를 먼저 작성하도록 요청했습니다.

```text
입력 프롬프트 흐름:
"pikchr 코드를 생성할 수 있는 웹 UI를 설계해줘.
좌측 사이드바: 오브젝트를 선택할 수 있는 팔레트 및 정의 영역
우측 사이드바: 추가된 오브젝트 리스트 및 속성 편집기
센터스테이지: pikchr이 실시간 렌더링된 화면 (마우스 조작 및 상호작용)
하단 바: pikchr 코드 에디터
우측 사이드바를 선택하면 해당 오브젝트를 센터스테이지와 하단 코드 블럭에 하이라이트해야 해.
구문에 이상이 없을 때는 바로 렌더링하고 문제가 있다면 원인을 알려줘야 해.
먼저 설계부터 진행할거니까 개발까지 수행하지 마."
```

이 요청에 따라 Antigravity CLI는 기본 설계 문서와 디렉터리 구조, 다국어(i18n) 체계를 구성했습니다.

설계 내용 확인 후 구현을 진행했으며, React, TypeScript, Tailwind CSS 기반의 프로젝트 구성과 WebAssembly 컴파일러(`pikchr-js`) 연동이 이루어졌습니다.

```pikchr

arrow dashed from E.e to G.w "캔버스 요소 클릭" above
```

## 2. 주요 문제 해결 과정

브라우저에서 직접 기능을 실행해 보며 확인된 주요 문제점들과 이를 수정한 과정은 다음과 같습니다.

### 1) 캔버스와 코드 매핑: 문장(Statement) 탐지

Pikchr 문법은 다음과 같은 특징이 있습니다:
- 세미콜론(`;`)으로 문장 구분
- 개행(`\n`)으로도 문장이 끝나지만, 역슬래시(`\`)로 이어지는 연속행은 제외
- 한 줄에 여러 문장이 작성되는 인라인 형태(`box; box; box;`) 가능

초기 정규식 기반 처리로는 인라인 세미콜론이나 연속행, 주석 내부의 문자가 정확히 구분되지 않는 문제가 있었습니다.

> **제공 피드백:**  
> `"Nested blocks 예제에서 N3: box wid .4 "n3"; D3: box wid .3 "d3" 처럼 ';'으로 문장이 끝나는데 식별이 제대로 안 돼. 원인을 찾아 개선해 줘."`

이를 해결하기 위해 문자 단위로 상태를 추적하는 스캐너를 작성하도록 했습니다.
- 각 문장의 절대 문자 범위(`startChar`, `endChar`, `startLine`, `endLine`)를 계산하고 고유 ID를 부여
- 렌더링된 SVG 엘리먼트에 `data-stmt-id` 속성을 주입하여 캔버스 요소와 코드 문장을 연결

---

### 2) 텍스트 삭제 현상과 시각적 하이라이트 오버레이 적용

초기에는 캔버스에서 요소를 선택했을 때 에디터의 기본 선택 기능(`setSelectionRange`)을 사용해 해당 코드를 드래그 선택 상태로 만들었습니다.

이 방식에서는 요소를 선택한 상태로 키를 입력할 경우 선택된 문장 전체가 지워지는 문제가 발생했습니다.

> **사용자 피드백:**  
> `"소스 블럭을 선택할 때 셀렉션은 안해도 되고 선택된 영역을 하이라이트 하기만 하면 돼. 값을 입력할 때 문장 자체가 삭제되는 현상이 있으니까 개선해 줘."`

텍스트 선택 범위를 직접 변경하는 대신, Textarea 배경 레이어에 위치를 계산해 시각적 하이라이트만 표시하는 오버레이 컴포넌트로 구조를 변경했습니다. 이를 통해 텍스트 입력 상태를 유지하면서 선택된 문장의 위치를 표시할 수 있게 되었습니다.

---

### 3) 키워드 자동완성(Autocomplete) 구현 및 테스트 코드 작성

Pikchr의 다양한 수식어와 앵커 문법 입력을 보조하기 위해 자동완성 기능 설계를 요청했습니다.

> **사용자 피드백:**  
> `"pikchr 문법을 참고해서 code view에 키워드 입력에 따른 자동완성 제시 기능을 적용하고 싶어. 설계 문서를 생성해 줘."`  
> *(설계 확인 후)*  
> `"계획대로 구현해 줘."`  
> *(구현 완료 후)*  
> `"지금 구현한 기능을 테스트 코드를 생성해서 모든 기능을 검증해 줘."`

문맥 분석기와 추천 엔진을 구현하고, Vitest 기반의 단위 및 통합 테스트 53개를 생성하여 동작을 검증했습니다.

### 4) 실사용 테스트를 통한 UI/UX 개선

직접 에디터를 다루며 발견된 동작 오류와 개선 사항을 정리하여 순차적으로 수정을 요청했습니다.

| 상황 | 피드백 내용 | 처리 방식 |
| :--- | :--- | :--- |
| **자동완성 목록 잘림** | *"자동완성 컨텍스트 박스가 브라우저 영역을 벗어나서 보이지 않을 때가 있어. 로케이션 설정 기능을 개선해 줘."* | 뷰포트 하단 경계 감지 시 팝오버를 상단으로 전환하는 로직 적용 |
| **속성 편집 시 키워드 누락** | *"`box same 'Parser'`를 속성 창에서 수정하면 `same` 키워드가 삭제돼. 속성에서 지원하지 않는 키워드를 삭제하는 버그를 수정해 줘."* | 속성 외의 기존 수식어를 유지하도록 정규식 파서 개선 |
| **모바일 키보드 스크롤** | *"모바일 UI에서 코드 블럭의 끝까지 스크롤할 수가 없어. 개선해 줘."* | 키 입력 시 커서 위치로 뷰포트를 자동 스크롤하도록 수정 |
| **렌더링 반영 시점** | *"코드가 변경되고 렌더링되기 전이면 '문법 검증 완료' 텍스트를 '수정됨'으로 변경하고 클릭 시 바로 렌더링해줘."* | 디바운스 대기 중 클릭 시 즉시 렌더링되는 상태 버튼 추가 |
| **패널 크기 조절** | *"사이드바와 하단 바의 영역을 사용자가 조절할 수 있도록 개선해 줘."* | 드래그 조절 패널 및 `localStorage` 크기 저장 기능 추가 |

코드 수정 외에도 Git 커밋 및 푸시 작업 역시 프롬프트를 통해 요청하여 정리했습니다.

## 3. 정리

이번 작업 과정에서 확인된 바이브 코딩 방식의 특징은 다음과 같습니다:

1. **설계 정의의 필요성**: 무작정 구현을 시작하기보다 전체 인터페이스 구조와 처리 흐름을 사전에 정리해 두는 것이 수정 비용을 줄이는 데 도움이 되었습니다.
2. **구체적인 피드백의 중요성**: 단순 오류 보고보다는 현상과 원하는 동작 방식(예: '선택' 대신 '하이라이트'만 적용)을 명확히 전달할 때 의도에 맞는 결과물을 얻을 수 있었습니다.
3. **지속적인 실사용 검증**: 생성된 코드가 정상적으로 빌드되더라도 실제 사용자 인터랙션에서 예외 상황이 발생할 수 있으므로, 직접 사용하며 확인하는 과정이 필수적이었습니다.
